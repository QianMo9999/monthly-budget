# 月账本 · 预算与结余

一个纯前端的月度记账小应用：记收入、定预算、结算实际支付、记录零星开销和预支，自动算出本月结余。
不需要联网、不需要服务器、不需要装 App —— 打开 `index.html` 就能用，数据存在你自己的设备上。

## 快速开始

**在电脑上试**

```bash
open index.html          # 直接双击打开也可以
```

**手机上用（推荐）**

把整个文件夹放到任意静态托管（GitHub Pages、Netlify、Vercel、公司内网 nginx 都行），
用手机浏览器打开后在 Safari 里点「分享 → 添加到主屏幕」，桌面就会出现「月账本」图标，
打开后是全屏的 App 体验，离线也能用。

**在电脑上起个本地服务**（等价于托管效果）

```bash
python3 -m http.server 8800
# 然后浏览器打开 http://127.0.0.1:8800
```

## 放到网上（一次性，之后手机直接用）

页面本身**不联网也能跑**（没有接口、没有 CDN，数据只在浏览器本地）。托管只是让手机有个网址能取到文件，
取到一次之后由 Service Worker 缓存到手机上，以后断网照常用。

**方式一：GitHub Pages（免费、长期有效）**

1. 在 GitHub 新建一个仓库（例如 `monthly-budget`），把本目录里的 `index.html`、`src/`、`icons/`、`sw.js`、`manifest.webmanifest` 传上去；
2. 仓库 `Settings → Pages → Source` 选 `Deploy from a branch`，分支选 `main`、目录选 `/ (root)`，保存；
3. 一两分钟后访问 `https://<你的用户名>.github.io/monthly-budget/`。

**方式二：拖拽部署（更省事）**

打开 `app.netlify.com/drop`（或 Cloudflare Pages 的 Direct Upload），把解压后的文件夹拖进去，立刻拿到一个 HTTPS 网址。

**手机上**

Safari 打开网址 → 底部分享按钮 → 「添加到主屏幕」→ 桌面出现「月账本」图标，打开就是全屏 App，断网也能用。

> 为什么必须 HTTPS：Service Worker（离线缓存）只在安全上下文里生效。局域网 `http://192.168.x.x` 这种地址拿不到离线能力。

## 功能

- **收入**：每个月单独设收入（默认取设置里的月收入，例如 8000），点顶部结余卡片即可修改。
- **预算项目**：名称、分类、计划金额、截止日期、备注；花完之后点「结算」填写**实际支付金额**，立刻反映到结余。
- **分次结算**：一个项目可以分几笔付完（定金 + 尾款），每笔都有自己的金额和日期；付满计划金额会自动标记完成，也可以在项目里手动「标记完成」。
- **按天重复的预算**（生活费这类）：填人数和**每人每天**的金额（每个人可以不一样），App 按天数自动算出总额、已经发生的部分、以及**后续还需要留多少预算**；也可以只算某一段日期（比如出差期间）。
- **生活费每日结算**：每天花多少填多少，**比计划少算「省下」，比计划多算「超支」**，两者都会立刻反映到结余里。没填的过去天数按计划推算，今天往后的天数算「还需要预留」。
- 当天 0 点起就按计划金额先记入「已发生」（这样当天不会虚高结余），你每天填了实际金额就以实际为准；「每天明细」默认收起，需要时点「展开」。
- **零星记账**：支出和**收入**都能记。不在预算内的开销按天分组、算每日小计；报销、卖闲置这类零星收入会加回结余。记账日期落在别的月份时，会自动记到对应月份。
- **预支（提前为后面月份花钱 / 预留）**：专门用来表示"这个月为下个月或更晚花的钱"，**不是借钱、不需要还款**。两种情况自动区分：
  - **已经花了**（比如 9 月就把 10 月的车票买了，扣款日已到）→ 钱真的出去了，**9 月实际剩余减少**；到 10 月这笔钱会**加回 10 月可用额度**，你把 10 月的「车票」预算记成已支付时刚好抵消，不会重复花第二次。
  - **只是预留**（比如 9 月为 11 月 3 日要扣的 500 元做预留）→ 钱还在卡里，**实际剩余不减**，但**结余里减掉这 500**，且一直保留到扣款日（10 月实际剩余里还有这 500，10 月结余减掉它）；11 月真正扣款后，11 月同样把这笔钱加回可用额度。
- **余额对账**：漏记了几笔？直接填「现在实际有多少钱」，App 把差额记成一笔调整，结余和实际剩余立刻对上；可以重新对账、撤销，历史记录保留。
- **自动结转**：本月结余自动带到下个月，也可以手动指定结转金额或关掉。
- **复制上月预算**：每月重复的固定支出（房租、话费…）一键带过来。
- **导出**：JSON 备份（换设备恢复用）和 CSV 表格（Excel / Numbers 打开）。
  - 「导出备份（覆盖同一个文件）」用固定文件名 `月账本备份.json`：手机走系统分享面板，选「存储到文件」时 iOS 会问**替换 / 保留两者**，选替换就覆盖旧的；电脑 Chrome/Edge 第一次选一下保存位置，之后每次导出**直接覆盖，不会再出现 (2)(3)**。
  - 「导出带日期的备份」保留成 `月账本备份-2026-09-24.json`，需要多个历史版本时用。
  - 超过 7 天没备份，页面顶部会自动提醒。
- **版本号**：设置里能看到当前版本（例如 `v1.4.0`），用来确认线上是不是已经更新到最新。
- **分类**：居住、餐饮、交通、水电燃气、通讯、医疗、教育、家庭、娱乐、购物、人情往来、旅行、储蓄理财、宠物、其他。

## 列表排序规则

- **预算**：未完成的排在前面（按计划金额从大到小），已完成的排在后面（按实际支付金额从大到小）。
- **记账**：按日期从新到旧，并按天分组、给出每天的小计。
- **预支**：未收回的排在前面，已收回的排在后面，同一组里按日期从新到旧。

## 结余是怎么算的

```
结余（顶部主数字）= 收入 + 上月结转 + 零星收入 + 上月预支转入 − 预算承诺额 − 零星支出 − 预支已支付 − 预支待预留 + 对账调整
实际剩余          = 收入 + 上月结转 + 零星收入 + 上月预支转入 − 预算已支付 − 零星支出 − 预支已支付 + 对账调整
预算承诺额        = Σ max(计划金额, 实际支付)  ← 普通预算：没花完的按计划留，超支的按实际扣
                  = Σ (已发生 + 还需预留)      ← 按天重复的预算（按天逐日结算）
预支已支付        = 付款日已到、钱真的出去了的部分（两个数字都扣）
预支待预留        = 付款日还没到、或更早月份登记至今未付的部分（只扣结余，不扣实际剩余）
上月预支转入      = 上个月替你付掉的那部分（归属本月的预支，只算已支付的）：
                   加回本月可用额度，你在本月为它记的预算结算时会刚好抵消
对账调整          = 最后一次对账填的实际余额 − 当时的账面余额
预算余额          = 预算计划合计 − 预算已支付
结余 + 未花预算 + 预支待预留 = 实际剩余
```

以月收入 8000、结转 500 为例：

| 项目 | 金额 | 说明 |
| --- | --- | --- |
| 收入 | 8000 | |
| 上月结转 | 500 | 上月结余自动带过来 |
| 房租（计划 2500 / 实际 2500） | −2500 | 已完成，按实际支付扣 |
| 餐饮（计划 1500，未完成） | 0 | 还没花，只占用预算额度 |
| 健身（计划 200 / 实际 260） | −260 | 超支 60，会单独提示 |
| 水电（计划 300 / 实际 250） | −250 | 省下 50，会单独提示 |
| 零星记账 | −50 | 奶茶 20 + 打车 30 |
| 预支（600 未还） | −600 | 还清后自动不再扣 |
| **结余（已扣预算）** | **3290** | 8000 + 500 − 4560（承诺额）− 50 − 600 |
| **实际剩余** | **4840** | 只扣已经花掉的 3010 |

「结余」把预算先留出来，所以它比「实际剩余」少，差额就是还没花掉的预算（上例 1550 = 餐饮 1500 + 水电省下的 50）。

几个约定：

- 预算项目「已完成」但没填实际金额时，按计划金额计算。
- 超支和节省只做提示，不会重复计入支出。
- 预支归还 / 报销的金额会从「预支未还」里扣掉，所以结余会跟着回升。
- 按天重复的预算逐日结算：已经结算过的天按你填的实际金额；过去但没结算的天按计划估算；今天及以后算「待预留」，今天填了就当天结清。
  于是 `计划总额 = 已发生 + 还需预留 + 省下`，超支的天数会让「已发生」变大。
- 按天重复的预算不要再逐笔记账，否则同一笔钱会被算两次。

## 提前买了下个月的东西（预支）

9 月买了 10 月的车票 700 元，点「预支 → 新增预支」填上，**归属月份默认就是下个月**（也可以改成下下个月）：

| | 9 月 | 10 月 |
| --- | --- | --- |
| 收入 | 8000 | 8000 |
| 上月结转 | — | 7300（9 月剩下的钱） |
| 上月预支转入 | — | **+700** |
| 车票（10 月预算，结算 700） | — | −700 |
| 提前支付车票（付款日已到） | **−700** | — |
| 结余 | 7300 | 15300 |

如果车票的**付款日还没到**（比如 9 月先记一笔、11 月才付）：

| | 9 月 | 10 月 | 11 月（付款日之前 → 之后） |
| --- | --- | --- | --- |
| 实际剩余 | 不扣（钱还在手里） | 不扣 | 付款前不扣，付款后扣 |
| 结余 | 扣 700（先预留） | 仍扣 700 | 付款后不再重复预留，改由结转体现 |

要点：

- 9 月扣掉 700，所以银行卡余额对得上（余额对账能校正）；
- 这 700 **不算 9 月的消费**，也不进 9 月的零星记账；
- 10 月自动带「上月预支转入 +700」，你在 10 月列「车票 700」的预算并结算时不会重复扣一次；
- 两个月合计：16000 收入 − 700 车票 = 15300 ✓
- 钱如果退回来了（退票、报销），在那条预支上点「收回」填金额：本月结余立刻回升，下个月的转入也同步减少。

## 漏记了怎么办（余额对账）

漏记几笔是常态，不用回头补。点概览「实际剩余」卡片上的**对账**，或者「设置 → 余额对账」：

1. App 先告诉你它算出来的**账面剩余**；
2. 你填**现在实际有多少**（银行卡 + 现金 + 零钱）；
3. 差额会自动记成一笔「对账调整」——实际比账面少，说明有支出漏记；实际比账面多，说明有收入漏记；
4. 保存后「实际剩余」正好等于你填的数字，顶部「结余」也同步校正，结转带到下个月。

多次对账不会重复叠加：每次都按最新账面重算差额，只保留最后一条生效，历史记录可以在对账面板里看到，也能一键撤销。

## 数据存在哪

- 默认存在浏览器的 **localStorage**（键名 `monthly-budget-state-v1`），关掉页面、换页、重启都不丢。
- 清空浏览器网站数据、或者用无痕模式，会丢掉数据 —— 所以请定期用「设置 → 导出备份（JSON）」存一份到「文件 / iCloud 云盘」。
- 换手机或换浏览器：把 JSON 文件传过去，用「设置 → 导入备份」恢复。
- iPhone 上的小提示：Safari 对「7 天没访问过的网站」可能回收网页存储，**添加到主屏幕之后不受这个限制**，所以建议装成主屏幕 App 用。
- 如果浏览器不允许本地存储（隐私模式等），页面顶部会出现黄色提示条，此时只能用导出功能保存数据。

```bash

node --test tests/core.test.js tests/dom.test.js

# 真实浏览器交互自检（需要本机装了 Chrome）：会模拟点击整个流程并截图

```

`selftest.sh` 做的事：新增预算 → 填实际支付金额结算 → 记一笔零星开销 → 新增预支并归还 →
导出 CSV 校验 → 切换月份 / 年份 → **关掉页面重新打开，确认数据还在**。
